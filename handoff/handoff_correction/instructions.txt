ZERPAI ERP - HANDOFF CORRECTION INSTRUCTIONS

This handoff correction bundle contains all the modified and uncommitted files representing the resolved bug fixes and UI/UX improvements.

================================================================================
I. DIRECTORY LAYOUT AND INTEGRATION INSTRUCTIONS
================================================================================
The `handoff_correction` folder replicates the exact directory structure of the main project.

To integrate these files:
1. Open the `handoff_correction` directory.
2. Select all directories (e.g., `backend`, `lib`) and files (e.g., `.gitignore`, `paths.txt`, `instructions.txt`).
3. Copy them.
4. Paste them directly into the root directory of your main project (e.g., `c:\Users\User\Documents\work\zerpai-new`), overwriting all matching files.

Alternatively, you can copy each file to its destination manually using the paths listed in "paths.txt".

================================================================================
II. SUMMARY OF CHANGES MADE IN EACH FILE
================================================================================

1. .gitignore
   - Cleanup/maintenance.

2. backend/drizzle/schema.ts & backend/src/db/schema.ts
   - Removed 'transactionBinId' and 'transactionBinLabel' fields from the 'purchase_receives' table schema to clean up unnecessary fields.

3. backend/src/modules/purchases/purchase-orders/services/purchase-orders.service.ts
   - Updated the PO status calculations query to include receives with 'intransit' status, ensuring accurate status updates for purchase orders that are partially/fully received in transit.

4. backend/src/modules/purchases/purchase-orders/utils/po-status.ts
   - Included 'intransit' receives in status updates calculation logic alongside the finalized 'received' ones.

5. backend/src/modules/purchases/purchase-receives/services/purchase-receives.service.ts
   - Implemented safe upsert/increment logic on batch stock layers: when inserting a batch stock layer, it queries first. If a layer exists with the same product, batch, bin, warehouse, and entity, the service updates/increments its quantity instead of creating a duplicate layer (which previously threw unique constraint database errors).
   - Removed obsolete 'transaction_bin_id' and 'transaction_bin_label' database updates/creation parameters.

6. lib/modules/purchases/bills/presentation/pages/purchases_bills_create.dart
   - Resolved formatting issues and checked syntax/import validations.

7. lib/modules/purchases/purchase_orders/presentation/pages/purchases_purchase_orders_create.dart

   - Declared state variables '_currentPoTxnStatus' and '_currentPoTxnUpdatedAt' in the state class.
   - Refactored the detail panel cache guard check condition: the transaction summary is now re-fetched whenever the selected PO ID, status, or updatedAt timestamp changes.
   - Fixed the caching bug by calling clearCache('purchase-orders') and invalidating the detail order provider whenever status changes or "Refresh List" is tapped.

9. lib/modules/purchases/purchase_receives/presentation/pages/purchases_purchase_receives_create.dart
